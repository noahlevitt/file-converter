# Known issues and limits

Behaviour that is intentional but surprising, and small quirks found while documenting the code. None of them
produces a wrong import file silently. Each entry says where it lives, in case it should be changed later. Broader
limits (landlines, browser refresh, restarts, speed) are in the README under "Known limits".

## Conversion

| # | Issue | Effect | Where |
|---|---|---|---|
| 1 | **Several numbers in one cell are only split where they are clearly separate** (since 0.11.0 each gets its own row). Not split: digits run together with no separator (`51655501005165551212`), and shorthand for a second number (`516-555-0100/0101`). A vanity number next to another number (`1-800-FLOWERS 516-555-0100`) isn't recognised as a number of its own. With labels written between numbers and no separator, a label at the end of the cell means labels follow their numbers. | Run-together digits are a bad row (`too many digits`); shorthand and vanity cases import the one full number found. Nothing is guessed. | `normalizers.split_phones` |
| 2 | **Mobile vs landline can't be told apart** from the number alone. | Every different valid number gets a row, including landlines that can't receive texts. A carrier lookup (paid per number) would be needed. | — |
| 3 | **Phone typo repair can still be wrong**: an 11-digit value whose extra digit was really a wrong digit (the remaining 10 digits form someone else's number); an area code that doesn't exist read as the file's own when the customer's real area code was a different one; a 7-digit number given the file's main area code when the customer lives elsewhere (restored in 0.20.0, removed in 0.9.0). Real area codes are never changed. | Repaired numbers are imported and marked orange; check them under *Problems only*: a wrong area code texts a stranger. | `normalizers._repair_phone` |
| 4 | **Birthdays in the last two years** are treated as "no year" (`1600`). | A real anniversary from last year loses its year (month and day are kept). Chosen because Excel silently adds the current year to dates typed without one. | `normalizers.normalize_date` |
| 5 | **A whole birthday column sharing one year** (50%+ of 10+ values, or 80%+ of 5+) is treated as a placeholder year. | A small file of genuinely same-year birthdays would get `1600`. Very unlikely for real customers. | `normalizers._placeholder_year` |
| 6 | **Intersections in a one-line address** (`Main St & 1st Ave`) keep only the first street in address line 1. | Only relevant for formats with address fields (not the current import format). | `transforms._ADDRESS_TAGS` |
| 7 | **The whole file is held in memory** while converting. | Very large files (millions of rows) need a server with more memory. About 150,000 rows took 25 seconds in testing. | `engine.convert` |
| 28 | **The size check before reading covers .xlsx, .xlsm and .ods only.** An .xls sheet can't exceed 65,536 x 256 cells (reading the largest possible one needs about 1.5 GB). .xlsb (rare) isn't checked, so a stray value in its last cell could still stop the app. The limit is an estimate from measurements (about 60 bytes per cell of the block plus 150 per value) against 80% of the computer's memory. | A sheet that fits in memory is read as before; one that doesn't is refused with a message naming the far cell. For bigger honest files, give the server more memory. | `sheetsize.check_sheet_size` |
| 23 | **Header detection needs a column of phone numbers, emails or dates** to tell labels from values. Files without one (names only) or a header with no customers fall back to a guess and show an "unsure" warning. A title or report line directly above headerless customers (`Guest export`, `Store, Kravit Bayside`) becomes the column names. In very small one-column files with shifted or junk rows the header can be read as a data row. Measured on 54,000 generated files: header found in 98.9–99.9% of files with one, 95.7–96.7% exact for files without one. | No customer is lost: a row with a valid phone or email is never used as the header or skipped above it (also checked by a test over 1,000 generated files). A header read as data becomes one bad row. Check the warning and the raw preview. | `reader.detect_header` |
| 24 | **Activity dates are imported as written**, also `01/01/1900`, `01/01/1970` (a common "empty" timestamp) and dates in the future. Decided in 0.15.0: only birthday and anniversary get a placeholder year. | Such dates can skew "visited in the last 30 days" segments. *Check for mistakes* warns about future activity dates. | `normalizers.normalize_date` |
| 30 | **A quote mark that is never closed in a CSV is recognised by what follows it** (0.16.0): the cell is still open at the end of the file, it ends at the opening quote of a later cell (`,"Smith, John"`), or it is still open after 20 lines that look like rows of the file (the same number of commas). Two cases can't be told from a real note: when the next quote mark in the file ends a cell (a `"` typed as a ditto mark, `55"`), the rows between stay joined into one cell, as before 0.16.0. With 3+ such lines (files of 3+ columns) a warning names the row; with fewer lines, or in a file of 1–2 columns, nothing is said. A real multi-line note of 20+ lines that each have exactly as many commas as a row is cut into rows. A quote in the middle of a cell (`5" tall`) is an ordinary character, as in Excel. | Customers inside a joined cell are missing from the import: check the row the warning names, and have the client's file fixed. A cut note shows as rows with no phone number (bad rows) and a warning. | `reader._read_text_grid`, `reader._quote_check`, `reader._lenient_grid` |
| 33 | **Without a chosen sheet, the first visible sheet with any value is read** (0.17.0; before, always the first sheet). A summary or instructions sheet in front of the customer list is read instead of it. | The warnings and the raw preview show which sheet was read; pick the right one under *File options* and click *Re-read file*. The import itself (and a re-run) uses the sheet that was read. | `reader._choose_sheet` |
| 34 | **Birth Month / Birth Day columns follow the date rules for numbers** (0.18.0 notes). A month of 13+ with a day of 12 or less is read the other way round, like `13/10/2026` in a US column (most likely the two were typed in each other's column). When the file also has a complete *Birthday* column, it is used only if most of its values have a year and it is filled for as many customers as the month and day columns; otherwise the parts win and the years in it are not used. | Check birthdays from split columns in *Side by side*; map the *Birthday* column by hand if it should win. | `heuristics._full_date_wins`, `dateparse._md` |
| 35 | **A combined date + time column pair reports a row with a time but no date** as a date that couldn't be read (blank, listed under *What changed*), where the date column alone would have been silently empty. | Information only; the row still imports. | `heuristics._named_time_partner`, `_time_partner` |
| 36 | **Excel error cells are restored for .xlsx, .xlsm, .xls and .ods, not .xlsb** (0.19.0). In .xls they need the `xlrd` package (in requirements.txt); an .ods written by something other than LibreOffice may not mark errors. | Such cells arrive empty, as before: a phone says "required value is missing", other fields are blank without a reason. | `sheeterrors.error_cells` |
| 37 | **Six-digit dates without separators can't show the order** (`150326` is 15 Mar 2026 or 26 Mar 2015). They are read month-first, then year-first, unless other values or the *Option* cell say day-first. | Set *Option* = `DMY` (or `YMD`) for such a column. | `normalizers._first_two_parts`, `dateparse._compact` |

## Mapping

| # | Issue | Effect | Where |
|---|---|---|---|
| 8 | **A column about a phone could still be matched in step 1** of the automatic mapping if its *values* look like phone numbers (e.g. a "Phone Verified" column that holds numbers). Step 2 never adds such columns. | Shows on the mapping page; fix with *Goes to* / *Skip*. | `heuristics.auto_map` |
| 9 | **The full-name split doesn't check for consent-looking headers.** "Subscriber Name" can be split into first/last name. | Only relevant for formats with name fields. Consent itself is only ever mapped by a person (since 0.14.0). | `heuristics.auto_map` step 4 |
| 10 | **Templates match on the set of column names**, ignoring order, capitalisation, spaces and punctuation (since 0.16.0 the template's columns are found in the file the same way; when two columns of the file differ only in punctuation, the one spelled exactly like the template is used, otherwise neither). Files without a header row don't use templates at all (since 0.12.1: never matched, never saved). | Two systems exporting identical column names with different meanings would share a template. Check the mapping page. Headerless files are mapped by hand each time. | `mapping.header_fingerprint`, `storage.find_template`, `mapping.has_generic_columns` |
| 11 | **Old templates keep old choices.** A template saved before a rule changed (e.g. one that mapped `phone4MarketingPreference`) is applied as saved. | Fix the mapping once and save with *Remember this mapping*, or delete the template. Phone fields using *First non-empty* are upgraded automatically. | `services.initial_mapping` |
| 31 | **A column named for another kind of number is still the phone column when nearly all its values are phone numbers** (90%+, 0.16.0). *Account Number*, *Order #*, *Loyalty ID* and similar names give no evidence for the phone field, but some loyalty systems use the phone number as the member number. | IDs that are 90%+ valid US phone numbers by chance are very unlikely. Check the mapping page when an ID column is used. | `heuristics.names_other_number`, `heuristics.auto_map` step 2 |
| 32 | **A fax column mapped by hand isn't kept by templates** (0.17.0). Fax numbers are never imported unless a person maps the column for that file; a template applied later drops it again, and the mapping page names the column. *Phone/Fax* and *Tel/Fax* columns count as fax columns, and a number labelled *Phone/Fax* in a cell counts as a fax. | If a client's fax column really holds phone numbers, set *Goes to* → `phone_number` on each file. | `Mapping.normalized`, `mapping.is_fax_column`, `normalizers._is_fax_label` |

## Claude (optional features)

| # | Issue | Effect | Where |
|---|---|---|---|
| 12 | **Phone masking covers the review's sample rows only.** The up-to-15 sample values per column (`AI_SAMPLE_VALUES`) sent with every Claude call, and the failed values sent by *Suggest fixes*, are not masked. | Lower `AI_SAMPLE_VALUES` or leave Claude off if no customer data may leave the company. | `ai._profile_payload`, `checks.mask_phone` |
| 13 | **Suggested fixes for values with a spaced three-character group of look-alike letters** (`516 5OO 0100`) are refused as having too few digits. `516-5OO-0100` works. | Rare; the value stays a bad row. | `ai.accept_repair` |

## App and operations

| # | Issue | Effect | Where |
|---|---|---|---|
| 14 | **`showErrorDetails = false`** (Streamlit 1.65 reads it as `"stacktrace"`): on an unexpected error users see the exception type and traceback, but not the message. | Set `showErrorDetails = "none"` in `.streamlit/config.toml` to hide errors from users completely. Full details are always in the server log. | `.streamlit/config.toml` |
| 15 | **Cancel takes effect at the next progress check:** the start of each field and every 2,000 rows. Not while the file is being read or the output written. | A cancel can take a few seconds on big files. | `jobs.ProgressTracker` |
| 16 | **If saving an uploaded file fails** (e.g. disk full), the import record stays *queued* until the next restart marks it *interrupted*. | Free disk space, restart, re-upload. | `storage.Store.create_import` |
| 17 | **Imports running during a restart** are marked *interrupted*. | Re-run them with one click. | `storage.mark_interrupted` |
| 18 | **Users page:** the "can't delete your own account" message only flashes briefly, because the page reloads right after. | Cosmetic. | `app.page_users` |
| 19 | **The "times included a time zone" count** in the mistake check also counts dash-separated dates ending in a year (`01-15-2024`). | The info line's number can be too high; conversion is unaffected. | `checks._ZONE_HINT_RE` |
| 20 | **No database migrations.** Tables are created if missing but never altered. | A future column needs an explicit `ALTER TABLE` (see DEVELOPMENT.md). | `storage.Store` |
| 21 | **Imports converted before an update keep their old output.** | Use *Re-run this import* to apply new rules. | — |
| 22 | **The light/dark toggle uses a browser-side workaround.** Streamlit can't switch theme per user from the server, so the toggle makes the browser tab report "dark" or "light" to Streamlit's automatic theme (no page reload, so nobody is signed out). It depends on Streamlit internals. | If a future Streamlit version changes them, the toggle stops having an effect (nothing else breaks); the app then follows the computer's setting. On a fresh page load the computer's setting shows for a moment before the saved choice applies. | `app.py` "Light / dark mode", `.streamlit/config.toml` |
| 26 | **"Download as CSV" in the app's tables** (the table toolbar Streamlit adds) writes values exactly as shown, so a formula from a client's file (`=HYPERLINK(…)`) is live if that download is opened in Excel. The *Rejected rows* download is safe (0.15.0). | Use the *Rejected rows* download, or set `disableDataExport = true` under `[client]` in `.streamlit/config.toml` to turn table downloads and copying off. | Streamlit, `.streamlit/config.toml` |
| 27 | **Values that couldn't be converted stay on the import record after the file purge**: up to 500 per field (`failed_values` in the summary, used by *Suggest fixes*), which can include phone numbers. | Customer values outlive `FILE_RETENTION_DAYS` in `data/converter.db`. They aren't shown or used once the files are gone. | `jobs.run_import`, `storage.purge_files` |
| 29 | **An unexpected error on one value is turned into a reason** (*couldn't be read (unexpected error, logged for the developer)*) instead of stopping the import (0.15.3). | Only that value is lost, but the cause is a bug or an input the code doesn't handle: it is written to the server log with the field name. Look there when the reason shows up. | `normalizers.normalize` |
